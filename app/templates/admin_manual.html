Golden path

Use this sequence every time. Do not skip verification just because the UI looks connected.

  1. 1Create tenantNr3
  2. 2Client logs inNr2
  3. 3Connect WhatsAppZernio
  4. 4Load SOTKnowledge
  5. 5Test liveWhatsApp

1. Create Tenant

  • Go to Add new tenant.
  • Enter business name, contact email, phone, and initial agent defaults.
  • Confirm the tenant appears in the sidebar.
  • Open the new tenant workspace and confirm runtime status is healthy.
  • Confirm the welcome email was sent or copy the fallback login details.
Minimum creation data:
- Business name
- Contact person
- Email
- Phone / WhatsApp
- Website
- Preferred language
- Initial AI Agent default

2. Client First Login

  • Client opens the dashboard link from the welcome email.
  • Client logs in with the temporary password.
  • Check that Nr2 loads without “could not load conversations”.
  • Client can edit company knowledge and agent personality later.

Do not treat tenant creation as complete until the dashboard route works for that tenant.

3. WhatsApp Connection

  • In Nr2, client clicks Connect WhatsApp.
  • Client authorizes their own Meta Business / WhatsApp account.
  • In Nr3, verify WhatsApp shows connected for the tenant.
  • Confirm strict provider/account allowlist exists for the tenant.
  • Send one real inbound WhatsApp test from a non-internal number.
WhatsApp go-live test:
1. Send: "Hi, which company is this?"
2. Confirm it reaches the correct tenant inbox.
3. Confirm Marina uses the correct company facts.
4. Trigger one escalation test.
5. Confirm no other tenant receives the message.

4. Source of Truth

  • Upload company information, services, prices, policies, and example answers.
  • Add website links when the website is trustworthy and current.
  • For regulated tenants, add clear “do not advise” boundaries.
  • Test questions that should be answered and questions that should escalate.

SOT is not decoration. If it is not in SOT or tenant config, assume Marina may not know it.

5. Tone & Timing

  • Run the Agent Personality wizard in Nr2 or add an Nr3 override.
  • Set response timing: preset, custom seconds, or random range.
  • For real clients, avoid instantly pushing appointments. Ask clarifying questions first.
  • Test in WhatsApp, not only the dashboard.

Good reply timing should feel human: one useful response after the customer finishes typing.

6. Go-Live Checklist

  • Tenant dashboard route returns 200.
  • Runtime health is 200 locally on the VPS.
  • WhatsApp connected badge is visible in Nr3.
  • SOT and tone are loaded and tested.
  • Escalation appears in Nr2 when triggered.
  • Backup/export is available before real traffic.
  • Rollback point exists before any risky change.

Standard Operating Rules

Internal

Never call UI-only state “done”. A feature is done only when backend confirms it and live verification passes.

Never connect a tenant without an allowlist. WhatsApp/Zernio account IDs must be tenant-scoped.

Never deploy risky changes without rollback. Snapshot first, deploy second, verify third.

Never trust one test message. Test company identity, SOT, escalation, and wrong-tenant isolation.
